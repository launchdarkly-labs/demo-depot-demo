Demo Depot

From a repo to the catalog in one tag

Install once, let Claude make the repo depot-ready, publish by tagging. Every launch gets its own LaunchDarkly project.

1

Install once

Per machine, about five minutes

  • Claude Code plugin (skill + MCP server)
/plugin marketplace add launchdarkly-labs/demo-depot-publish
/plugin install demo-depot@demo-depot
  • The ddu CLI (Node 20+; Docker only for ddu run)
npm i -g --allow-remote=root https://github.com/launchdarkly-labs/demo-depot-publish/releases/latest/download/demo-depot-cli.tgz
  • Tokens, in the portal under Settings: save your LaunchDarkly API token (launches run as you), create a Demo Depot API token, sign the CLI in
ddu auth login   # paste the ddp. token
ddu auth status
2

Make the repo depot-ready

Per demo, in Claude Code, inside the repo

Ask Claude:

Using the demo-depot skill, make this repo ready for Demo Depot.

The skill inventories the code and adds:

  • demo.yaml manifest: container, port, health check, parameters
  • ld/seed.json: the flags every launch starts with
  • DEMO.md talk track, cover image, publish workflow

Then check it yourself:

ddu validate .   # the checks the depot runs
ddu run          # local run, depot layout
3

Publish and launch

Repo must live in launchdarkly-labs or launchdarkly-demos

git commit -am "Depot-ready" && git push
git tag v0.1.0 && git push origin v0.1.0
  • GitHub Actions builds the arm64 image and uploads the manifest and seed
  • The depot verifies the version by launching it once (2 to 5 minutes), then DMs you on Slack
  • Any SE opens the catalog, clicks Launch, and gets their own URL and LaunchDarkly project

New version? Bump the tag: v0.1.1. Done for the day? Tear down from My Demos.

Or let Claude do all of it over MCP: "publish this and launch it when it's verified."
